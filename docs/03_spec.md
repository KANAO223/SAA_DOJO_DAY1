## 0. 画面の型

| | 選んだもの | 理由 |
|---|---|---|
| **LAYOUT** | `stage` | 課題が「途中でやめてしまう」であり、成立させたいことが「駅を決めた／経路を決めた／描いた のどこで止まっているかが分かる」こと。段階ごとに束ねる型がそのまま当てはまる |
| **TONE** | `pine` | 1行目が小学生の遊び・学びの道具。業種表の「教育・サービス・その他」にあたる |
| **DENSITY** | 🔮 `roomy` | 🔮 週2〜3本・1本40〜60分＝**1日あたり1本以下で、1件が重い**ため。元の件数が仮説なので 🔮 を付ける |
| **UNIT** | `本` | 路線は「1本、2本」と数える。「件」では路線に見えない |

### CATEGORIES（`stage` なので、これがそのまま「段階」になる。左から順に進む）

```
["駅えらび", "ルートぎめ", "下書き", "清書ずみ"]
```

🔮 この4段階は、「駅を決める → つなぎ方を決める → 鉛筆で描く → ペンで仕上げる」という進み方を仮に置いたもの。
   → 確かめ方: 「路線を作るとき、どういう順番でやってる？ 何ができたら『完成』？」

---

## 1. このツールが解くこと

**考えた空想路線が1本も消えずに残り、どこで止まっているかがひと目で分かるので、途中でやめる本数が減る。**

---

## 2. 使う人と、使う場面

- **使う人**: 空想好きな子鉄（男子小学生）本人。ひとりで操作する
- **いつ開くか**: 🔮 新しい路線を思いついたとき（電車の中・寝る前）と、続きを描こうとして「どれが途中だっけ」となったとき
   → 確かめ方: 「路線を思いつくのって、だいたいどんなとき？」
- **開いて最初にしたいこと**: 作りかけの路線が何本あるか、どの段階で止まっているかを見る

**言葉づかい**: 小学生が読むので、画面の文言はすべて**ひらがな混じりのやさしい日本語**にする。
「未対応」「進行中」ではなく「つくりかけ」「できあがり」。漢字を使うときはその学年で習う範囲に寄せる。

---

## 3. 画面（テンプレートの3画面をそのまま使う）

### 一覧（開いたとき最初に出る画面）

上から順に、こう並びます。

1. **数字の要約（3つ）** ── 「つくりかけ ◯本」／「7日いじょう ほったらかし ◯本」／「ぜんぶで ◯本」
2. **さがす欄と絞り込み** ── 路線名・通る駅で検索できる欄と、「つくりかけ／できあがり／ぜんぶ」の切り替え
3. **段階ごとに束ねた一覧** ── 「駅えらび」「ルートぎめ」「下書き」「清書ずみ」の順に束が並び、その中に路線が1本ずつ。各行に **路線名 / 通る駅 / 止まっている日数のバッジ / 思いついた日 / 操作ボタン**

> 0本のときは「まだ路線がありません。右上の『新しい路線』から1本つくれます」と出す。

### 新規登録 ── 路線を1本足す。項目は下の5つだけ

### 設定 ── 画面の名前を変える／見本データを入れ直す・全部消す

> ⚠ この画面に「やらないこと」「🔮の仮説」「出口の3点」「競合」は**出しません**。社内メモです。

---

## 4. データ項目

**5つまで。** テンプレートの `Record` 型をそのまま使います。

| 項目 | 型 | 必須 | 例 |
|---|---|---|---|
| 路線名（`name`） | 文字列 | ✔ 必須 | 「そうぞう1号線」 |
| いまの段階（`category`） | 4つから選ぶ | ✔ 必須（初期値「駅えらび」） | 「ルートぎめ」 |
| 通る駅（`stations`） | 駅名の配列（順番どおり） | 任意 | `["田端", "王子", "赤羽", "十条"]` |
| 思いついた日（`date`） | 日付 | ✔ 必須（初期値は今日） | 2026-08-21 |
| できあがったか（`done`） | はい／いいえ | ─（ボタンで切り替え） | いいえ |

> ルーレットで選ばれた10駅は、そのまま **「通る駅」の配列**に入ります（5-2章）。

---

## 5. 操作（3つまで）

| # | 操作 | 何が起きるか |
|---|---|---|
| 1 | **路線を1本つくる** | 路線名と通る駅を入れて保存すると、一覧の「駅えらび」の束に1本増える。リロードしても残る |
| 2 | **段階をすすめる**（編集で「いまの段階」を変える） | その路線が、いまの束から次の段階の束へ移動する |
| 3 | **できあがりにする** | 「つくりかけ」から外れ、上の数字の「つくりかけ ◯本」が1本減る |

> 削除も残しますが、これは「間違えて足したときの取り消し」であって、主役の操作ではありません。

## 6. やらないこと

`CLAUDE.md` 3章の3つ＋今回の範囲外。

1. **他の子と路線を見せ合う機能を作らない。** 共有・投稿・いいね・ランキングは作らない
2. **ログイン・課金・保護者向けの画面を作らない**
3. **外部の地図タイル（航空写真・道路地図）を読み込まない。** 地図は駅の点と線だけの自前SVGにとどめ、地図ライブラリも追加しない
4. **画像・写真のアップロードをしない**（描いた路線図の写真を貼る機能は作らない）
5. **駅データを editor から編集できるようにしない。** 駅の追加・座標の修正はコードの中だけ

> ⚠ **変更（2026-08-21）**
> もともとここには「地図に線を描かない／最短経路を計算しない／ルーレットを作らない／駅データを持たない」と書いていました。
> ユーザーの指示により、**この4つは 5-2章のとおり実装しました。** 上の5つが、いま残っている「やらないこと」です。

## 5-2. あとから足した機能（3行目の「ルーレット→最短経路→地図」にあたる部分）

| 何 | どう作ったか |
|---|---|
| **駅データ** | 東京23区の地下鉄以外の主な路線から **212駅** を `app/page.tsx` に埋め込み。緯度経度つき。**全駅ではなく抜粋**で、**座標はおおよそ（数百メートルの誤差あり）**。画面にもその旨を書く |
| **ルーレット** | 「ルーレットを まわす（10駅）」で、かぶらないように10駅を抽選し「通る駅」に入れる |
| **最短経路** | 「いちばん短い順に ならべる」で、選んだ駅を最短でつなぐ順番に並べ替える。**11駅までは Held-Karp で厳密解**、12駅以上は 近い駅から順につないで 2-opt。距離は緯度経度からの直線距離 |
| **地図** | ライブラリを使わず **SVGで自前描画**。全駅をうすい点、選んだ路線を線と番号つきの丸で描く。一覧の行の「ちず」ボタンと、新規登録・編集画面に出る |

> 「通る駅」は文字列から**駅名の配列**に変わりました（データ項目の数は5つのまま）。
> 前のバージョンで保存したデータは、読み込むときに区切って配列へ直します。

## 7. 完成条件

見れば誰でも Yes/No が判定できる形で3つ。

- [ ] 路線名に「そうぞう1号線」、通る駅に「田端 → 王子 → 赤羽」と入れて保存すると、一覧の**「駅えらび」の束の中に1本増える**。ブラウザを再読み込みしても消えない
- [ ] その路線を編集して「いまの段階」を「下書き」に変えると、**「駅えらび」の束から消えて「下書き」の束に現れる**
- [ ] 設定から全部消したあと一覧を開くと、**「まだ路線がありません」と、次に何をすればいいかが書かれた画面**が出る（真っ白にならない）

## 8. 保存方法

`localStorage` に1つのキーで保存する。キー名: **`rosen-data`**（画面の表示名は `rosen-appname`）

読み書きは必ず `useEffect` の中だけで行う（`CLAUDE.md` 5-2章の書き方に従う）。

※ 端末ごとの保存です。複数人での共有は第3回で扱います。
※ 名前・連絡先など個人が分かる情報は**集めません**（`docs/01_customer.md` の出口③参照）。
